# 21 · Convolutional Neural Networks: Building In What We Know About Images

**Part 3 — Deep learning** · Notebook 21 of 27

An MLP looks at an image as a list of 784 unrelated numbers. Shuffle the pixels, the same way for every image, and the MLP doesn't care: it learns just as well, because it never used the fact that neighboring pixels belong together. That's a lot of wasted knowledge. We *know* two things about images: **local patterns matter** (edges, corners, textures are made of nearby pixels), and **a pattern means the same thing wherever it appears** (an edge in the top-left corner is still an edge in the bottom-right).

A **convolutional neural network** (CNN) builds both facts into its architecture. Instead of connecting every pixel to every unit, it slides small learned filters across the image, reusing the same weights everywhere. The result has far fewer parameters, learns faster from less data, and handles shifted inputs gracefully. CNNs started the deep learning boom in 2012 and are still the workhorse of image processing.

    with torch.no_grad():
        for xb, yb in dl:

## 2. Convolution from scratch

A **convolution** slides a small grid of weights (a **filter** or **kernel**) over the image. At each position, it multiplies the filter by the patch of pixels under it, element by element, and sums: one output number per position. The output is a new image, the **feature map** (or activation map), that is large wherever the patch resembles the filter (ISYE W10, CX lecture 12):

$$O[i, j] = \sum_{u=-d}^{d}\sum_{v=-d}^{d} I[i + u,\, j + v]\; K[u, v] \;+\; b.$$

(Strictly, this is *cross-correlation*; mathematical convolution flips the kernel first. Deep learning libraries all compute the version above and call it convolution; since the kernel is learned, the flip doesn't matter.)

##CODE
def conv2d_naive(img, kernel, stride=1, padding=0):
    """Plain loops, exactly the formula: slide the kernel, multiply, sum."""
    img = np.pad(img, padding); kh, kw = kernel.shape
    H = (img.shape[0] - kh) // stride + 1; W = (img.shape[1] - kw) // stride + 1
    out = np.zeros((H, W))
    for i in range(H):
        for j in range(W):
            patch = img[i * stride:i * stride + kh, j * stride:j * stride + kw]
            out[i, j] = (patch * kernel).sum()
    return out

out = conv2d_naive(tiny, k_vert)

## 3. Padding, stride, and the output size

Two knobs control the geometry (CX lecture 12):

- **Padding** $P$: add a border of zeros so the filter can be centered on edge pixels. With $P = (F-1)/2$ the output keeps the input's size ("same" padding).
- **Stride** $S$: move the filter $S$ pixels at a time instead of 1, shrinking the output.

For an input of width $W$ and a filter of width $F$:

$$W_{\text{out}} = \left\lfloor\frac{W - F + 2P}{S}\right\rfloor + 1.$$

CX's example: a 32 × 32 image with a 5 × 5 filter, no padding, stride 1 gives $(32 - 5)/1 + 1 = 28$. 🎚️ **Try it:**

##CODE

## 4. Convolution layers: channels and filters

Real images have **channels** (3 for RGB), and after the first layer every feature map is a channel too. So a filter in a convolution layer spans **all input channels**: for a 32 × 32 × 3 image, a 5 × 5 filter is really 5 × 5 × 3, and it produces one 2-D feature map. A layer has many filters, and their maps stack into the output's channels. CX's example: 6 filters of size 5 × 5 × 3 turn a 3 × 32 × 32 image into a 6 × 28 × 28 output, with $6 \times (5\cdot5\cdot3 + 1) = 456$ parameters (the +1 is each filter's bias). Then an activation (ReLU) is applied to every number.

Let's write a multi-channel convolution with NumPy, vectorized (the "im2col" trick: unroll every patch into a row so the whole convolution becomes one matrix multiplication, which is also how fast libraries do it), and check it against PyTorch's `F.conv2d`:

##CODE
def conv2d_im2col(x, w, b, stride=1, padding=0):
    """x: (C_in, H, W), w: (C_out, C_in, k, k), b: (C_out,). Returns (C_out, H_out, W_out)."""
    C_in, H, W = x.shape; C_out, _, k, _ = w.shape
    x = np.pad(x, ((0, 0), (padding, padding), (padding, padding)))
    H_out = (H + 2 * padding - k) // stride + 1; W_out = (W + 2 * padding - k) // stride + 1
    cols = np.empty((H_out * W_out, C_in * k * k))
    for i in range(H_out):
        for j in range(W_out):
            cols[i * W_out + j] = x[:, i * stride:i * stride + k, j * stride:j * stride + k].ravel()   # one patch per row
    out = cols @ w.reshape(C_out, -1).T + b                                                       # one big matrix product
    return out.T.reshape(C_out, H_out, W_out)

r_ = np.random.default_rng(0)
x_ = r_.normal(size=(3, 32, 32)); w_ = r_.normal(size=(6, 3, 5, 5)); b_ = r_.normal(size=6)
ours = conv2d_im2col(x_, w_, b_)
theirs = F.conv2d(torch.tensor(x_)[None], torch.tensor(w_), torch.tensor(b_))[0].numpy()
print(f"output shape {ours.shape}; max difference from F.conv2d: {np.abs(ours - theirs).max():.2e}")
print(f"parameters: {w_.size} weights + {b_.size} biases = {w_.size + b_.size}   (CX lecture 12: 6 × (5·5·3 + 1) = 456)")

dense = 3 * 32 * 32 * 6 * 28 * 28
print(f"a fully connected layer with the same input and output sizes would need {dense:,} weights ({dense // 456:,}× more)")

##MD
That last line is the payoff of **weight sharing**: the same 456 numbers are reused at all 784 output positions, instead of a separate weight for every input–output pair. Fewer parameters means less data needed and less overfitting, and the sharing is exactly the assumption "a pattern means the same thing anywhere".

## 5. Pooling and translation invariance

**Pooling** shrinks feature maps by summarizing each small window, usually **max pooling** over 2 × 2 windows with stride 2 (CX lecture 12): keep the largest value, halving height and width. Mean pooling averages instead. Pooling has no parameters. It reduces computation for later layers, and it makes the output less sensitive to exactly *where* a feature occurred: if an edge moves by one pixel within a window, the max is unchanged.

We'll measure how much in section 6.

## 6. A CNN for Fashion-MNIST

The classic layout (ISYE W10: *"convolution + ReLU → pooling → … → flatten → fully connected → softmax"*): a few convolution blocks that turn the image into a stack of small, many-channel feature maps, then a small MLP that classifies them.

```
input 1×28×28
→ conv 3×3, 32 filters, ReLU   → 32×28×28
→ max pool 2×2                 → 32×14×14
→ conv 3×3, 64 filters, ReLU   → 64×14×14
→ max pool 2×2                 → 64×7×7
→ flatten                      → 3136
→ linear 128, ReLU, dropout    → 128
→ linear 10                    → class scores
```

##CODE
class SimpleCNN(nn.Module):
    def __init__(self, c1=32, c2=64, hidden=128, dropout=0.3):
        super().__init__()
        self.features = nn.Sequential(nn.Conv2d(1, c1, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
                                      nn.Conv2d(c1, c2, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2))
        self.classifier = nn.Sequential(nn.Flatten(), nn.Linear(c2 * 7 * 7, hidden), nn.ReLU(), nn.Dropout(dropout), nn.Linear(hidden, 10))
    def forward(self, x): return self.classifier(self.features(x))

##CODE
def shifted_acc(model, dx):
    model.eval()
    with torch.no_grad():
        Xs = torch.roll(Xva_t, shifts=dx, dims=3)
        if dx > 0: Xs[..., :dx] = Xva_t.min()
        elif dx < 0: Xs[..., dx:] = Xva_t.min()
        return (model(Xs.to(device)).argmax(1).cpu() == yva_t).float().mean().item()

mlp_trained = mlp_fn(); fit(mlp_trained, Xtr_t, ytr_t, epochs=8, verbose=False)
shifts = list(range(-6, 7))
acc_mlp = [shifted_acc(mlp_trained, d) for d in shifts]; acc_cnn = [shifted_acc(cnn, d) for d in shifts]
fig, axes = plt.subplots(1, 2, figsize=(14, 4), gridspec_kw=dict(width_ratios=[1, 1.4]))
ex = Xva_t[3, 0]
axes[0].imshow(torch.cat([torch.roll(ex, d, 1) for d in (-4, 0, 4)], 1), cmap="gray_r"); axes[0].axis("off"); axes[0].set_title("the same image shifted −4, 0, +4 pixels")
axes[1].plot(shifts, acc_mlp, "o-", label="MLP"); axes[1].plot(shifts, acc_cnn, "o-", label="CNN")
axes[1].set(xlabel="horizontal shift of every test image (pixels)", ylabel="validation accuracy", title="Robustness to translation"); axes[1].legend()
fig.tight_layout(); plt.show()

##MD
Both models degrade, since neither was trained on shifted images, but the CNN degrades far more gracefully: its filters still fire on the shifted edges and textures, just in different places, and pooling absorbs small offsets. For the MLP, a shift moves every feature onto weights that were trained for different pixels. (Section 9 makes the CNN more robust still.)

## 8. Receptive fields: seeing more with depth

Each unit in the first conv layer sees a 3 × 3 patch of the input: its **receptive field**. A unit in the second layer sees a 3 × 3 patch of first-layer maps, each of which saw 3 × 3 pixels, so it sees 5 × 5 pixels; pooling doubles the reach of everything after it. Small filters stacked deep cover large regions while keeping parameters low (two 3 × 3 layers see as far as one 5 × 5 layer, with $2 \cdot 9 = 18$ instead of 25 weights per channel pair, plus an extra nonlinearity). We can measure the receptive field empirically: backpropagate from one unit in the middle of a layer's output and see which input pixels have nonzero gradient.

##CODE
def receptive_field(layers, upto):
    x = torch.zeros(1, 1, 28, 28, requires_grad=True); a = x
    for l in layers[:upto]: a = l(a)
    c = a.shape[-1] // 2; a[0, :, c, c].sum().backward()
    g = (x.grad[0, 0].abs() > 0).float(); rows = torch.nonzero(g.sum(1)).flatten()
    return g, (rows.max() - rows.min() + 1).item() if len(rows) else 0

probe = SimpleCNN(); probe.eval()
for p in probe.parameters(): nn.init.constant_(p, 0.1)                # positive weights: every connected path has a nonzero gradient
layers = [nn.AvgPool2d(2) if isinstance(l, nn.MaxPool2d) else l for l in probe.features]   # max-pool sends gradient to one pixel only; average pooling shows everything that *can* matter
stages = [(1, "after conv1"), (3, "after conv1 + pool"), (4, "after conv2"), (6, "after conv2 + pool")]
fig, axes = plt.subplots(1, 4, figsize=(15, 3.8))
for ax, (upto, nm) in zip(axes, stages):
    g, size = receptive_field(layers, upto)
    ax.imshow(Xva_t[img_i, 0], cmap="gray_r", alpha=0.35); ax.imshow(g, cmap="Reds", alpha=0.6)
    ax.set(title=f"{nm}: {size}×{size} pixels"); ax.axis("off")
fig.suptitle("Input pixels that can influence one unit at the center of each layer's output", y=1.02); plt.show()

## 9. Data augmentation

A CNN is translation-equivariant by design but only partly invariant, and it knows nothing about other natural variations (small rotations, flips, scale). **Data augmentation** teaches those by example: during training, randomly transform each batch (flip, shift, crop, rotate slightly) in ways that don't change the label. The model sees a different version of every image each epoch, which acts as a powerful regularizer, especially when data is scarce. Let's train on just **5,000** images, with and without random flips and shifts:

##CODE
def augment(xb, max_shift=2):
    """Random horizontal flip + random shift of up to max_shift pixels, independently for every image."""
    flip = torch.rand(len(xb), device=xb.device) < 0.5
    xb = torch.where(flip[:, None, None, None], xb.flip(3), xb)       # clothes are left-right symmetric
    padded = F.pad(xb, (max_shift,) * 4, value=float(xb.min()))       # pad with background, then crop a random 28×28 window
    dx, dy = torch.randint(0, 2 * max_shift + 1, (2, len(xb)))
    return torch.stack([padded[k, :, dy[k]:dy[k] + 28, dx[k]:dx[k] + 28] for k in range(len(xb))])

aug_models, aug_hist = {}, {}
for name, aug in [("no augmentation", None), ("random flips + shifts", augment)]:
    aug_models[name] = SimpleCNN(); aug_hist[name] = fit(aug_models[name], Xtr_t[:5000], ytr_t[:5000], epochs=30, augment=aug, verbose=False)
    print(f"{name:24s}: final val acc {aug_hist[name].val_acc.iloc[-1]:.1%}, train loss {aug_hist[name].train_loss.iloc[-1]:.3f}, val loss {aug_hist[name].val_loss.iloc[-1]:.3f}")
fig, axes = plt.subplots(1, 2, figsize=(14, 4))
for (name, h), col in zip(aug_hist.items(), [C["red"], C["blue"]]):
    axes[0].plot(h.epoch, h.train_loss, "--", color=col); axes[0].plot(h.epoch, h.val_loss, "-", color=col, label=name)
    axes[1].plot(shifts, [shifted_acc(aug_models[name], d) for d in shifts], "o-", color=col, label=name)
axes[0].set(xlabel="epoch", ylabel="loss", title="validation (solid) vs training (dashed) loss, 5,000 images"); axes[0].legend()
axes[1].set(xlabel="horizontal shift of every validation image (pixels)", ylabel="validation accuracy", title="robustness to shifts"); axes[1].legend()
fig.tight_layout(); plt.show()

##MD
With augmentation, training is harder (the dashed training loss stays higher, since each epoch brings "new" versions of every image) and the gap between training and validation loss shrinks. On the clean validation set the two models end up about equally accurate: Fashion-MNIST photos are centered and consistently oriented, so the validation images rarely look like the augmented ones. The payoff shows on the right: the augmented model is far more robust to shifts it was taught to ignore. Whether augmentation raises test accuracy depends on whether the test data actually varies in the ways you augment for; on real-world photos (varied framing, lighting, orientation) it usually does, and it's one of the most effective tools in practice. So augmentation is how you encode *invariances you know the task has* without changing the architecture; choosing them is a modeling decision (a horizontal flip is fine for clothing, wrong for digits like 2 vs. 5 or for text).

## 10. Deeper networks: VGG blocks, batch norm, residual connections

The history of image classification on **ImageNet** (1.3 million photos, 1,000 classes; ISYE W10) is largely a history of going deeper:

| Year | Network | Depth | Key idea | Top-5 error |
|---|---|---|---|---|
| 2012 | AlexNet | 8 | ReLU, dropout, GPUs | 15.3% |
| 2014 | VGG | 16–19 | stacks of 3 × 3 convolutions | 7.3% |
| 2014 | GoogLeNet | 22 | parallel filter sizes (Inception) | 6.7% |
| 2015 | **ResNet** | 152 | **residual connections** | 3.6% |

Simply stacking more layers stops working past a certain depth: a 56-layer plain network trains to a *higher training error* than a 20-layer one (He et al., 2015). That's not overfitting; it's an optimization problem (vanishing gradients, notebook 19). The **residual block** fixes it by learning a correction to the identity:

$$\text{output} = \text{ReLU}\big(x + f(x)\big), \qquad f = \text{conv} \to \text{BN} \to \text{ReLU} \to \text{conv} \to \text{BN}.$$

If the best thing a block can do is nothing, it just learns $f \approx 0$. And the gradient has a direct path back through the "+ x" shortcut, so very deep stacks stay trainable. Let's compare plain and residual networks of the same depth on our data:

##CODE
class Block(nn.Module):
    def __init__(self, ch, residual=True, bn=True):
        super().__init__(); self.residual = residual
        norm = (lambda: nn.BatchNorm2d(ch)) if bn else (lambda: nn.Identity())
        self.f = nn.Sequential(nn.Conv2d(ch, ch, 3, padding=1), norm(), nn.ReLU(), nn.Conv2d(ch, ch, 3, padding=1), norm())
    def forward(self, x): return F.relu(x + self.f(x)) if self.residual else F.relu(self.f(x))

class DeepNet(nn.Module):
    def __init__(self, n_blocks=16, ch=32, residual=True, bn=False):
        super().__init__()
        self.stem = nn.Sequential(nn.Conv2d(1, ch, 3, padding=1), nn.ReLU())
        self.blocks = nn.Sequential(*[Block(ch, residual, bn) for _ in range(n_blocks // 2)], nn.MaxPool2d(2),
                                    *[Block(ch, residual, bn) for _ in range(n_blocks - n_blocks // 2)], nn.MaxPool2d(2))
        self.head = nn.Sequential(nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(ch, 10))   # global average pooling
    def forward(self, x): return self.head(self.blocks(self.stem(x)))

deep_hist = {}
for res in [False, True]:
    name = f"{'residual' if res else 'plain'}, 34 layers"
    net = DeepNet(n_blocks=16, residual=res)
    deep_hist[name] = fit(net, Xtr_t[:6000], ytr_t[:6000], epochs=3, lr=1e-3, verbose=False)
    print(f"{name}: {n_params(net):,} parameters, training loss by epoch {deep_hist[name].train_loss.round(3).tolist()}, val acc {deep_hist[name].val_acc.iloc[-1]:.1%}")

def grad_norms_at_init(residual, n_blocks=16):
    torch.manual_seed(0); net = DeepNet(n_blocks=n_blocks, residual=residual); net.train()
    F.cross_entropy(net(Xtr_t[:64]), ytr_t[:64]).backward()
    return [blk.f[0].weight.grad.norm().item() for blk in net.blocks if isinstance(blk, Block)]
fig, axes = plt.subplots(1, 2, figsize=(14, 4))
for (name, h), col in zip(deep_hist.items(), [C["red"], C["blue"]]):
    axes[0].plot(h.epoch, h.train_loss, "o-", color=col, label=name)
axes[0].axhline(np.log(10), color=C["muted"], ls=":", label="log 10 (chance)"); axes[0].set(xlabel="epoch", ylabel="training loss", title="training loss (6,000 images, no batch norm)"); axes[0].legend()
for res, col in [(False, C["red"]), (True, C["blue"])]:
    axes[1].semilogy(range(1, 17), grad_norms_at_init(res), "o-", color=col, label="residual" if res else "plain")
axes[1].set(xlabel="block (1 = nearest the input)", ylabel="gradient norm of the block's first conv", title="gradient reaching each block at initialization"); axes[1].legend()
fig.tight_layout(); plt.show()

##MD
The plain 34-layer network doesn't learn at all: its loss sits at $\log 10$, chance level, for every epoch. The residual network with the very same layers and parameters trains normally. The right panel shows why: in the plain network the gradient shrinks by orders of magnitude on its way back through the blocks, so the early layers get no signal; the shortcuts deliver a usable gradient to every block. (We left out batch normalization here to isolate the effect. With batch norm, as in real ResNets, plain networks of moderate depth do train, which is part of why BN mattered so much in 2015; at greater depths the residual connections still win.) `DeepNet` also uses **global average pooling** (average each final feature map to one number) instead of a big fully connected layer, which cuts parameters dramatically.

> 🤔 **Question: Do people still train CNNs from scratch?**
>
> For new image tasks, usually not. The standard practice is **transfer learning**: take a network pretrained on ImageNet (available in `torchvision.models` with one line), replace its last layer with one for your classes, and fine-tune on your data. The early layers' edge and texture detectors are useful for almost any image task, so a few hundred labeled images can be enough. Since about 2020, **vision transformers** (notebook 25's architecture applied to image patches) compete with CNNs at large scale, and the best modern CNNs (ConvNeXt) borrowed ideas back from them.

## 11. What is the network looking at?

Two simple ways to ask a trained CNN which pixels mattered for a decision:

- **Saliency map** (Simonyan et al., 2013): the gradient of the predicted class's score with respect to the input pixels. Large magnitude = changing this pixel would change the score most.
- **Occlusion** (Zeiler & Fergus, 2014): slide a gray patch over the image and record how much the correct class's probability drops. Large drop = the network relied on that region.

##CODE
cnn.eval()
picks = [int(np.flatnonzero(yva_t.numpy() == c)[0]) for c in (0, 1, 7, 8, 9)]
fig, axes = plt.subplots(3, 5, figsize=(14, 8.2))
for col, i in enumerate(picks):
    x = Xva_t[i:i + 1].clone().to(device).requires_grad_(True)
    score = cnn(x)[0, yva_t[i]]; score.backward()
    sal = x.grad[0, 0].abs().cpu()
    with torch.no_grad():
        base = F.softmax(cnn(x), 1)[0, yva_t[i]].item(); occ = np.zeros((28, 28)); cnt = np.zeros((28, 28))
        for r in range(0, 22, 2):
            for c in range(0, 22, 2):
                xo = x.detach().clone(); xo[..., r:r + 7, c:c + 7] = 0.0
                drop = base - F.softmax(cnn(xo), 1)[0, yva_t[i]].item(); occ[r:r + 7, c:c + 7] += drop; cnt[r:r + 7, c:c + 7] += 1
        occ /= np.maximum(cnt, 1)
    axes[0, col].imshow(Xva_t[i, 0], cmap="gray_r"); axes[0, col].set_title(f"{CLASSES[yva_t[i]]} (p = {base:.2f})", fontsize=10)
    axes[1, col].imshow(sal, cmap="hot"); axes[2, col].imshow(occ, cmap="RdBu_r", vmin=-np.abs(occ).max(), vmax=np.abs(occ).max())
    for a in axes[:, col]: a.axis("off")
axes[1, 0].text(-6, 14, "saliency\n|∂score/∂pixel|", ha="right", va="center", fontsize=10); axes[2, 0].text(-6, 14, "occlusion:\nprob. drop\nwhen hidden", ha="right", va="center", fontsize=10)
plt.show()

##MD
The two methods tell different stories, which is itself a lesson. The raw-gradient saliency maps are speckled all over the image, including the background: single-pixel gradients of a ReLU network are notoriously noisy (refinements such as SmoothGrad average them over many noisy copies of the input, and integrated gradients average along a path from a blank image). Occlusion is coarser but far easier to read: hiding a specific region (red) costs the most probability, such as the bag's handle area, the sneaker's toe, or the boot's heel. Such maps are useful sanity checks (a model that relies on the background or a watermark is cheating), but they should be read with care: different attribution methods can disagree, and none is guaranteed to reflect what the model truly relies on.

## 12. Summary

| Idea | What it builds in | Effect |
|---|---|---|
| **Local filters** | patterns are made of nearby pixels | few weights per filter |
| **Weight sharing** | a pattern means the same thing anywhere | translation equivariance; tens of thousands of times fewer parameters than dense layers |
| **Pooling** | exact position matters less than presence | smaller maps, partial invariance |
| **Depth** | features are hierarchical (edges → parts → objects) | large receptive fields with small filters |
| **Augmentation** | known invariances (shifts, flips…) | regularization, robustness |
| **Residual connections** | layers learn corrections to the identity | very deep networks trainable |

**Output size:** $W_{\text{out}} = \lfloor(W - F + 2P)/S\rfloor + 1$. **Parameters of a conv layer:** $C_{\text{out}}(C_{\text{in}}F^2 + 1)$.

The same idea, a layer whose structure matches the structure of the data, drives the next notebook: **recurrent networks** share weights across **time** instead of space.
